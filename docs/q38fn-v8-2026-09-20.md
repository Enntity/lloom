# Q38FN TP2 v8: larger BF16 cache and fused PLE/QSA

Recipe v8 retains NVIDIA's pinned Flash-Next checkpoint and the existing
vLLM serving stack. It raises the per-rank BF16 KV budget from 20 to 28 GiB
and backports the PLE residual and QSA output-gate fusions from
[vLLM PR 55309](https://github.com/vllm-project/vllm/pull/55309), including its
rounding follow-up. Full-vocabulary MTP3, GPU-resident TP2 PLE, prefix retention
1600, 262144 context, batch 8192, four active requests and eight queued requests
are unchanged.

The model revision remains `fab0aecb760cec45227f6656abcaafa11abca87a`, vLLM
remains `e962733e08d10f7ca65dac4df99e116460b8b174`, and the image remains
`vllm/vllm-openai@sha256:df871f170ee7070fbdce162bde08fb616e311570c948a620be0d4b33fe02f87b`.
No weight, vocabulary or KV-precision substitution is involved.

## Qualification

The 28 GiB serving run passed all **39 gateway cases**: five smoke cases
(including reasoning, streaming tools, a tool round trip and vision), fourteen
workload cases, thirteen multi-prefix retrieval/tool cases, and seven
near-limit retrieval/concurrency/tool cases. All responses were attributed to
the isolated local candidate without cloud fallback. The identical fused
kernels passed 22 upstream numerical cases on each host.

| Measurement | Recorded v7 | v8, September 20 |
| --- | ---: | ---: |
| BF16 KV budget per rank | 20 GiB | 28 GiB |
| Logical cache-token capacity | 1,343,310 | 1,881,768 (+40.1%) |
| Median short-prose decode | 39.45 tokens/s | 40.11 tokens/s |
| Cold 30K prompt, time to first token | 9.76 s | 10.57 s |
| Warm 30K prompt, time to first token | 0.79 / 0.77 s | 0.80 / 0.79 s |
| 239,656-token retrieval, cold total | 80.17 s | 83.08 s |
| Same retrieval, warm total | 1.70 s | 1.91 s |

The measured capacity gain is the principal benefit. Decode was essentially
unchanged; cold and near-limit latency did not improve against the historical
baseline. The near-limit repeat reused 236,800 tokens and returned the exact
early/middle keys, as did four simultaneous repeats and the structured tool
call. No change in production eviction rate was measured.

Available host memory after the workload was 12.08 GiB on the head and
13.50 GiB on the worker. The head swapped no pages out during inference; the worker swapped out only 28 KiB.
The head did read about 108.1 MiB back from swap; this is not a claim of zero
paging. Full machine and process receipts remain in the private experiment
record; the selected measurements are in
[qualification.json](../benchmarks/decision/2026-09-20-q38fn-v8/qualification.json).

This is one serving qualification against the recorded September 9 v7
workload, not a fresh paired benchmark or a production eviction-rate study.
More allocated cache provides capacity to retain more prefixes; the test does
not establish better model quality or a particular reduction in production
evictions. The full-model gateway cases exercise CUDA's opaque QSA owner path
and the PLE custom operation, supplementing the upstream helper/kernel tests.

## Memory decision

A preliminary 32 GiB budget booted, but a separate numerical-test CUDA process
on the head failed three fixture allocations before entering the fused kernel.
Its other 19 cases passed; all 22 worker cases passed. The head's same 22
cases then passed in isolation before model loading. No numerical mismatch
was reported. We selected 28 GiB to leave additional allocation headroom and
ran the serving workload at that budget only. This does not establish that
ordinary serving at 32 GiB necessarily fails.

Checkpoint loading can cause transient swap growth, so qualification records
both startup state and `/proc/vmstat` around inference. The serving gate checks
less than 512 MiB of swap-out during the workload and more than 8 GiB of
available host memory afterward, on each host. Admission reserves 110 GiB per
host; this includes room beyond the reported 63.61 GiB model allocation and
28 GiB KV pool. These Spark systems expose about 121.7 GiB to Linux.

## Integration and rollback

`nvidia-e962733e-v8/apply-stack.py` composes the baseline and fusion manifests,
validates all payloads and source hashes before writes, and accepts only known
pristine, baseline or final bytes. A restart verifies baseline-only files as
well as fused files. The hybrid block-size fixes remain separately guarded.
The preserved v7 backend and archived recipe remain available for rollback;
the two recipes must not run simultaneously on the same pair. LLooM config
reload stops the removed experimental runtime, so canonical promotion requires
a backend restart even when it reuses the same container and bootstrap.

The newer replay-boundary change in PR 54713 requires scheduler architecture
absent from this pinned base, so the qualified v7 retention behavior remains.
The existing mixed-MTP loader fix is retained for the pinned checkpoint;
this is not a claim of compatibility with all newer ModelOpt metadata.
FP8 KV, reduced draft vocabularies and the still-open deterministic-QSA work
were not included.

Validation includes the repository test suite, syntax/format/lint checks,
interchange validation, package install smoke, exact-image patch/restart
checks, independent code review, GPU numerical cases and attributed gateway
requests. The prior unrelated unused-variable lint warning remains.
