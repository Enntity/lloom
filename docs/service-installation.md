# Linux gateway service persistence

`lloom service install` manages the current user's `lloom.service`. It never
uses sudo, writes a system service, or changes model-container residency.
A generated unit runs the installed Node and LLooM entrypoint with an absolute
configuration path, restarts on failure, and keeps retrying when a configured
private interface has not appeared yet. It never silently changes the bind address.

Preview and apply:

```sh
lloom service install --config ./gateway.json --json
lloom service install --config ./gateway.json --enable-linger --apply --yes
lloom service doctor --config ./gateway.json --json
```

The caller's numeric user ID must have lingering enabled. Installation verifies
that state; `--enable-linger` authorizes `loginctl enable-linger` if needed.
Permission failures require an authorized login session; the command never
claims persistence when verification fails. Uninstall leaves lingering unchanged
because other user services may depend on it.

Use `--environment-file /absolute/path` for an existing service environment file.
Pass the same custom path to subsequent `service doctor`, stop and uninstall
commands so their unit comparison uses the installed environment-file path.
The file is loaded before expanding the configuration; existing shell variables
retain precedence for inspection. Otherwise an existing `~/.config/lloom/env` is included. Keys are never written
into the unit. `--admin-api-key-env NAME` selects the inspection credential from
the invoking environment; the service still needs its own environment file or
other persistent configuration. `--expect-unit HASH` guards a previously reviewed
unit hash. A missing explicitly selected environment file is an error.

Service commands use the current user home; alternate `--home` directories are
refused. Use `--config` to select a configuration elsewhere. Loaded units with
drop-in overrides require operator migration before installer control.

Only units marked as generated by this installer may be replaced, stopped or
removed. Unmarked existing units require operator migration. A changed running
unit is refused: drain and stop it before replacing it. Installation does not
restart a running gateway under a different executable or configuration.
The unit uses `KillMode=process`: gateway termination leaves managed child model
processes available, matching the CLI gateway shutdown contract.
An exclusive operation lock rejects concurrent installers; after a crash, inspect
the previous operation before removing its `.lock` file.

`service doctor` checks unit ownership and content, enablement, active state,
restart policy, lingering, local bind address, authenticated gateway node ID,
service/gateway PID agreement, environment-file presence and Docker availability
when a configured managed runtime needs Docker. A failing check sets a nonzero
exit status. JSON errors retain partial-operation and recovery receipts.

```sh
lloom service stop --config ./gateway.json --apply --yes
lloom service uninstall --config ./gateway.json --apply --yes
```

Stop and uninstall affect the gateway service only. Model files, configuration
and managed inference containers remain available. Failed installation restores
the prior unit and service enablement where possible, with backup paths and
individual failed recovery steps in its receipt. Operator edits discovered during
recovery are preserved and reported as requiring attention.

## Verification limits

Automated coverage uses temporary files, injected service-manager commands and
synthetic gateway responses. It covers logout persistence prerequisites, missing
interfaces, failed unit writes/enable/start, ownership, credential selection,
identity mismatch and compensating recovery. It does not prove a physical host's
logout or reboot behavior. After an authorized installation, qualify the target
from a second machine: record its node identity and gateway response, log the
service user out, verify the gateway again, and repeat after an authorized reboot.
Record failures and service journal evidence without publishing credentials.

Unit syntax follows the [systemd service documentation](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html).
